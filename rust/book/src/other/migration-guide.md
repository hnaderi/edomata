# Migration guide for Scala and Java users

This guide is for teams who know the Scala library (or its Java API) and want to use, or move to, the Rust port. The port keeps the **semantics, invariants and on-disk formats**, so a migration can be gradual: Rust and Scala services can run side by side on the same database.

## Crate mapping

| Scala module | Rust crate |
|--------------|------------|
| `core` | `edomata-core` |
| `backend` | `edomata-backend` |
| `postgres` | `edomata-postgres` |
| `skunk`, `doobie` | `edomata-sqlx` (one driver, `sqlx::PgPool` as the transactor) |
| `skunk-circe`, `skunk-jsoniter`, `skunk-upickle`, `doobie-*` | `edomata-serde` (`serde` + `serde_json` is the only serializer) |
| `munit` | `edomata-testkit` |
| `saas`, `saas-skunk` | `edomata-saas`, `edomata-saas-sqlx` |
| `java-api` | `edomata-simple` |
| `backend-tests`, `e2e` | `edomata-backend-tests`, `edomata-e2e` (test-only) |
| *(none)* | `edomata-broker`, `edomata-kafka`, `edomata-rabbitmq` |

The full, suite-by-suite mapping is in the [porting map](porting.md).

## Sharing a database

Nothing changes on disk:

- **Tables and DDL** are byte-for-byte identical (`PGSchema`, `SaaSPGSchema`), for both naming strategies (`PGNaming::schema` = `"ns".journal`, `PGNaming::prefixed` = `ns_journal`) and every payload type. Golden tests compare the Rust output with files generated by the Scala code.
- **Queries** match the Skunk / Doobie `Queries.scala`: same columns, ordering, `on conflict` upserts, unique-violation handling (`23505` → `VersionConflict`).
- **Payloads** default to `jsonb`, written in the native PostgreSQL binary format like the Scala codecs. JSON written by Circe, jsoniter (including jsoniter's `msgpack`, which writes JSON bytes) and uPickle's JSON codec is readable by `edomata-serde`, provided your Rust types serialize to the same JSON shape (see below).
- **Snapshots, commands, migrations** use the same tables, so a Rust process resumes where a Scala one stopped. The cross-language test (`rust/crates/edomata-e2e/tests/cross_language.rs`) has Scala write events, commands, outbox items and a snapshot, Rust read them and append, and Scala verify the result.

### Matching the JSON shape

Circe's generic derivation of Scala 3 enums encodes a case as `{"CaseName": {fields}}`, including parameterless cases (`{"Opened": {}}`). In serde, use struct variants everywhere (`Opened {}`) so that the externally-tagged encoding matches, and `#[serde(rename_all_fields = "camelCase")]` (or per-field `rename`) for camelCase field names. `BigDecimal` fields are JSON numbers: `rust_decimal::Decimal` with `rust_decimal::serde::float` reads and writes them. `edomata_serde::compat::upickle_option` handles uPickle's `Option` encoding. The `edomata-e2e` crate is a worked example against the Scala `accounts` domain.

### Known limitation: uPickle `msgpack`

Payloads written by uPickle's `msgpack` codec (real MessagePack in `bytea` columns) **cannot be read** by the Rust port, because `serde_json` is the only serializer. Migrate such journals to JSON with an event migration before sharing them with Rust, or keep them on the Scala side.

## Language mapping

| Scala | Rust |
|-------|------|
| `F[_]: Monad`, `IO` | `async fn` / `Future`; Tokio as the default runtime (no `F[_]` parameter anywhere) |
| `Id` for tests | `futures::executor::block_on` or `#[tokio::test]` |
| `NonEmptyChain[T]` | `NonEmpty<T>` (`nonempty![...]`) |
| `Chain[T]`, `List[T]` | `Vec<T>` |
| `ValidatedNec[R, T]`, `EitherNec[R, T]` | `Result<T, NonEmpty<R>>` |
| `Decision[R, E, A]` | `Decision<R, E, A>` (`Accepted { events, result }`, `Rejected(reasons)`, `InDecisive(result)`) |
| `ResponseD`, `ResponseE`, `Action`, `DecisionT` | same names (`Action` and `DecisionT` are futures) |
| `Edomaton[F, Env, R, E, N, A]` | `Edomaton<Env, R, E, N, A>` |
| `Stomaton[F, Env, S, R, E, A]` | `Stomaton<Env, S, R, N, A>` |
| `DomainModel` + `ModelTC`, `CQRSModel` | `DomainModel`, `CqrsModel` traits (`perform`, `apply_all`, `dsl`) |
| `Domain[...]`, `App.router`, `dsl.*` | `model.dsl::<C, N>()`, `dsl.router`, `dsl.state`, `dsl.decide`, `dsl.publish`, ... |
| `flatMap`, `>>`, `as`, `void` | `and_then` (alias `flat_map`), `then`, `replace`, `void` |
| `modifyS`, `decideS`, `set` | `modify_s`, `decide_s`, `set` |
| `validate` / `assert` overloads | `validate_with` / `validate_one`, `assert_with` / `assert_one` |
| `edomata.syntax.all.*` | `edomata_core::syntax::*` (`accept`, `reject`, `into_decision`, `to_accepted`, `to_rejected`, `to_accepted_or`, `to_decision`) |
| `Resource[F, Backend]` | `Backend` value with `close().await` |
| `Backend.builder(Service).use(driver)...build` | `Backend::builder(model, dsl).driver(driver)...build(codecs)` / `build_default()` |
| `SkunkDriver("ns", pool)` / `from(naming, pool, skipSetup)` | `SqlxDriver::for_namespace("ns", pool)` / `new_with(naming, pool, skip_setup)` |
| `BackendCodec[T]` givens | `SqlxCodec<T>` values (`SqlxCodec::<T>::jsonb()`) |
| `fs2.Stream` | `futures::Stream` (`BoxStream`), `TryStreamExt::try_collect` |
| `Notifications` (`Queue.circularBuffer`) | `Signal` over `tokio::sync::Notify` |
| `SkunkHandler` / `DoobieHandler` | `SqlxHandler<N>` (closure with the transaction's `PgConnection`) |
| `munit` `DomainSuite` (`expect`, `expectRejection`, ...) | `edomata-testkit` (`expect`, `expect_rejection`, ...) usable from any runner; commands are timestamped `Instant.MIN` / `DateTime::<Utc>::MIN_UTC` |
| `given AuthPolicy[Auth]` | an `AuthPolicy<Auth>` value passed to `SaaSCqrsService::new(policy, mk_rejection)` |
| `SaaS.guardedRouter`, `unsafeUnguardedRouter` | `saas.guarded_router`, `saas.unsafe_unguarded_router` |

Behavioural differences are recorded in the [ADRs](../design/index.md); the main ones: programs have no error channel (a failing effect is a panic or a `BackendError` from the storage, ADR 0005); the `Traverse` law set of `Decision` is not ported (no `Traverse` in Rust, ADR 0004); `Response`, the deprecated Scala alias, is not ported.

## For Java users

The Java API (`edomata-java-api`) maps to `edomata-simple`:

| Java | Rust |
|------|------|
| `JDomainModel.create(initial, transition)` | `ClosureModel::new(initial, transition)` |
| `JDecision` | `SimpleDecision` |
| `JAppResult` | `AppResult` |
| `JCommandHandler.create(ctx -> ...)`, `JRequestContext` | `CommandHandler::new(|ctx| ...)` / `new_async`, `Context` |
| `JCodec.of(encoder, decoder)` | `ClosureCodec::new(encoder, decoder)`, or `serde_codec::<T>()` for serde types |
| `JBackendBuilder.forDoobie(model).namespace(..).dataSource(..).eventCodec(..).build(runtime)` | `SimpleBackend::builder(model).namespace(..).pool(..).serde_codecs().build().await` (or `build_blocking(runtime)`) |
| `JBackend.handle(handler, cmd)` → `CompletableFuture<JEither<List<R>, Unit>>` | `backend.handle(&handler, cmd).await` → `Result<Result<(), Vec<R>>, SimpleError>` |
| `JJournalReader`, `JOutboxReader` | `SimpleJournal`, `SimpleOutbox` (vectors) |
| `EdomataRuntime` | `SimpleRuntime` (`create()` owns a Tokio runtime, since Rust has no global one) |
| `JPGSchema` | `SimplePGSchema` |
| `JEither` | `Result` |
| `IllegalArgumentException` / `IllegalStateException` | `SimpleError::InvalidNamespace` / `MissingConfig` |

The [Simple API](../backends/simple-api.md) chapter walks through a complete example.

## What is new in Rust

- **Broker distribution**: `OutboxRelay` / `JournalRelay` with Kafka and RabbitMQ publishers, leader election and at-least-once delivery with stable ids ([Distributing events](../backends/brokers.md)).
- **Cross-process wake-ups**: `with_outbox_notify_channel` / `with_journal_notify_channel` on the drivers plus `postgres::listen`.
- **In-memory driver** reproducing the PostgreSQL constraints, for tests and prototypes.
- **DDL under an advisory lock** when several replicas create tables at once.
- `wasm32` support for `edomata-core` (built in CI).

## Step by step

1. Point a Rust service at the existing database with the same namespace and naming strategy (`schema` unless you used `PGNamespace.prefixed`).
2. Define your event, state and notification types with serde derives matching the stored JSON; verify with a small program that reads the journal (`backend.journal().read_all()`).
3. Run the Rust and Scala services side by side; they share the `commands` table, so a command handled by one is redundant for the other.
4. Move processes (outbox consumers, projections) over; `OutboxConsumer` marks items exactly like Scala's.
5. Retire the Scala service.
