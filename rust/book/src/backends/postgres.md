# PostgreSQL (sqlx)

`edomata-sqlx` is the PostgreSQL backend: one driver replaces the Scala Skunk and Doobie drivers and shares their tables and payloads. The code of this page is compiled as part of the workspace (`rust/book/samples/src/running.rs`).

## Install

```toml
[dependencies]
edomata-core = { path = "rust/crates/edomata-core" }
edomata-backend = { path = "rust/crates/edomata-backend" }
edomata-sqlx = { path = "rust/crates/edomata-sqlx" }
edomata-serde = { path = "rust/crates/edomata-serde" }  # serde codecs (jsonb by default)
sqlx = { version = "0.8", default-features = false, features = ["postgres", "runtime-tokio", "chrono", "uuid"] }
tokio = { version = "1", features = ["rt-multi-thread", "macros"] }
```

## Defining codecs

Codecs are values of type `SqlxCodec<T>`. For serde types, `SqlxCodec::<T>::jsonb()` (or `::json()`, `::bytea()`) is all you need, and `build_default()` picks `jsonb` codecs automatically. Event-sourced backends need codecs for events and notifications, plus one for the state when persisted snapshots are used; CQRS backends need codecs for the state and the notifications.

Any type implementing `edomata_backend::Codec<T>` (format, `encode` to bytes, `decode` from bytes) can be wrapped with `SqlxCodec::new`.

## Table prefix mode

By default each aggregate gets its own PostgreSQL schema. To keep every table in one schema (for instance with Flyway), use prefixed naming: tables become `domainname_journal`, `domainname_outbox`, ... and no `CREATE SCHEMA` is executed. Constraint and index names are prefixed too (`domainname_journal_pk`).

{{#include ../../samples/src/running.rs:prefixed}}

`PGNaming::schema_str("x")` / `PGNaming::prefixed_str("x")` validate the namespace (a PostgreSQL identifier); `PGNamespace::from_string` does the same and gives the parsed namespace.

## Using with Flyway

If you manage your schema with Flyway (or another migration tool), extract the DDL and disable automatic table creation.

### 1. Generate the migration SQL

`PGSchema` returns one standalone statement per element (`CREATE TABLE`, `CREATE INDEX`), byte-for-byte identical to the Scala library's output:

```rust,ignore
{{#include ../../samples/src/running.rs:flyway}}
```

Copy the output into a migration file (e.g. `V1__create_accounts_tables.sql`). The optional `relay_checkpoints` table of `edomata-broker`'s journal relay is generated separately by `PGSchema::relay_checkpoints`.

### 2. Disable automatic setup

`new_with(naming, pool, true)` prevents the driver from executing any DDL, so Flyway has full control of the schema. The migration runner (`SqlxMigrations`) still creates its own `migrations` table, as in Scala.

## Cross-process wake-ups

`with_outbox_notify_channel(channel)` and `with_journal_notify_channel(channel)` make the driver raise `NOTIFY channel` in the writing transaction, so that a relay or process in another process can `LISTEN` instead of polling (`edomata_broker::postgres::listen`). Off by default; the Scala drivers have no equivalent.

## Compatibility with the Scala backends

- Tables, constraints, indexes and DDL are identical (golden tests against files generated by the Scala `PGSchema`).
- Payloads written by the Scala Circe, jsoniter (JSON and `msgpack`, which writes JSON bytes) and uPickle JSON codecs are readable; only uPickle `msgpack` (real MessagePack in `bytea`) is not, since `serde_json` is the only serializer.
- A cross-language test (`rust/crates/edomata-e2e/tests/cross_language.rs`) has Scala write, Rust read and append, and Scala verify on one database.
