# ADR 0007: Codecs, `jsonb` by default and the sqlx wire bridge

- Status: accepted
- Date: 2026-09-25
- Milestone: 4 (codecs)

## Context

Scala offers six codec modules (Circe, jsoniter-scala and uPickle, for Skunk
and for Doobie), each building a `BackendCodec[T]` (`Json`, `JsonB` or
`Binary`) from the library's typeclasses. The plan replaces them all with one
crate built on `serde_json`, storing payloads as `jsonb` by default, writing
the PostgreSQL binary `jsonb` format directly, and proving that payloads
written by the Scala codecs remain readable.

## Decisions

1. **One codec type.** `SerdeCodec<T>` implements `edomata_backend::Codec<T>`
   for any `T: Serialize + DeserializeOwned`. It is a small `Copy`
   value carrying only the `PayloadFormat`; `Default` is `jsonb`. The bytes
   are always compact JSON (`serde_json::to_writer` into a `Vec<u8>`), so a
   `bytea` payload written by this codec is JSON too, like jsoniter's
   `msgpack` codec (which writes JSON bytes despite its name).

2. **Bytes, not values.** The `Codec` trait works on `Vec<u8>` / `&[u8]`, so
   drivers never build a `String` or a `serde_json::Value`. With the `sqlx`
   feature, `edomata_serde::pg` provides wire wrappers implementing
   `sqlx::Encode` / `Decode` / `Type` for `Postgres`:
   - `JsonbPayload`: version byte `1` + UTF-8 JSON (binary `jsonb`), the
     same bytes `sqlx::types::Json` would send;
   - `JsonPayload`: the JSON text;
   - `ByteaPayload`: raw bytes (delegating to `Vec<u8>`);
   - `PgPayload`: a runtime-dispatched enum whose `Encode::produces`
     reports the actual column type, for drivers configured with a
     `PayloadFormat` value.
   Decoding accepts both text and binary wire formats and both `json` and
   `jsonb` column types, so reading a `json` column with a `jsonb` codec (or
   the reverse) works.

3. **sqlx 0.8, MSRV 1.88.** sqlx 0.9 requires rustc 1.94, and even sqlx 0.8's
   transitive dependencies (`icu`, pulled in via `url` → `idna`) require 1.88, so the workspace MSRV
   moved from 1.85 to 1.88 (June 2025). The CI `msrv` job pins that version.

4. **Golden payloads are generated by Scala.**
   `examples/src/test/scala/GoldenPayloads.scala` (test scope; it adds the
   jsoniter macros as a test dependency of `examples`) writes the bytes each
   Scala codec produces for the same sample ADT. The Rust test decodes them
   with the matching `serde` representation and re-encodes them
   byte-for-byte:

   | Scala codec | representation |
   |-------------|----------------|
   | Circe `generic.auto` | externally tagged; parameterless cases as `Closed {}`; `None` → `null` |
   | jsoniter `JsonCodecMaker.make` | `#[serde(tag = "type")]`; `None` fields omitted (`skip_serializing_if`) |
   | uPickle `ReadWriter.derived` | `#[serde(tag = "$type")]` inside an `#[serde(untagged)]` wrapper because parameterless cases are bare strings; `Option` as a 0/1-element array via `compat::upickle_option` |

   uPickle's `msgpack` codec writes real MessagePack; the test asserts that
   `serde_json` rejects it, which documents the known limitation.

5. **SQL is tested against the docker-compose database.** `tests/sql.rs`
   stores payloads through each wrapper, checks `pg_typeof`, queries with
   `->>` and `@>`, and reads back through the codec. It uses `DATABASE_URL`
   (default `localhost:5432`, the compose instance).

## Consequences

- Users migrating from uPickle keep their JSON shape with two attributes;
  users migrating from Circe or jsoniter need one or none.
- MessagePack payloads must be migrated (an `EventMigration` cannot help,
  since it works on JSON text); the migration guide (milestone 10) says so.
- `edomata-sqlx` binds payloads with `PgPayload` and never touches
  `serde_json::Value`.
